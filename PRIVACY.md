# Privacy

AfterWatch stores only your interface language and platform visibility/order preferences locally. It does not store watch history, send telemetry, create accounts, or operate a backend. Initial suggestions use the browser UI language; no IP geolocation, country detection, or external language service is used.

Opening the popup reads the active page's movie, series, and episode titles and metadata, including series/season relationships and IMDb URLs in that metadata. Episode detection also examines the current URL's pathname, excluding query parameters and fragments. The pathname is not included in destination searches or stored. The information is processed in popup memory. It does not read browser history, cookies, form values, passwords, page comments, or video content. JSON-LD references are resolved only within the page, with no external lookup.

On a matching MUBI film page, the extension also parses a size-limited embedded film record to read its localized title, supplied original title, slug, and release year. Player detection checks the film ID against the numeric player pathname, including the legacy record location. It reads only the current film, not recommendation records, and does not request another language version or send that record elsewhere.

Streaming adapters read scoped player title/subtitle text or the browser's media-session title on recognized playback pages. Video elements are checked only for their presence; audio/video content, playback positions, and DRM data are not read. Prime detail title artwork contributes only its alternative text, not the image. Apple detail routes and Prime's explicit episode tab can supply a content type.

Disney's custom player keeps its title/subtitle in page JavaScript. On its recognized player route only, a one-time MAIN-world script reads these two bounded text fields and the pathname. It returns no account/profile information, artwork, tokens, cookies, or full player object. It does not change the page, listen for messages, install a timer, or make an API request. A failed read leaves ordinary detection and manual entry available.

On YouTube, the extension reads only the current upload ID from the watch URL's `v` parameter, or a supported embed/Shorts/live pathname. Other query parameters and fragments are not returned, stored, or sent to destinations. The ID gates the current watch heading and video-bound metadata. An optional one-time MAIN-world read accesses only `ytInitialPlayerResponse.videoDetails.videoId` and its bounded `title`; it returns only the current ID and title, not the full response. Descriptions, comments, channel/account data, tokens, streaming data, and upload dates are not collected. Title suggestions are processed locally and require a user selection. Raw titles and IDs are kept only in popup memory. No YouTube API key or network lookup is used. Apart from these two bounded readers, extraction stays in Chrome's isolated world.

Clicking Ekşi Sözlük or Reddit includes the selected title in that site's search URL. An episode-specific search also includes the season and episode numbers. Reddit queries include the word discussion and use S01E02-style episode notation. Clicking Letterboxd includes a movie's detected IMDb ID or the selected movie/series title in a Letterboxd URL. The destination website handles its own requests, cookies, and account behavior. URLs can appear in browser history even though the extension itself does not keep a watch history.

Clicking IMDb sends either the selected work's metadata-provided IMDb ID or its title search to IMDb. Series and episode IDs are kept separate in popup memory. Episode-scope search includes explicit season/episode numbers. No request to IMDb, catalog API, or external service is made until the user clicks to open the destination. No IDs or media titles are saved as preferences.

`activeTab` supplies temporary access when you invoke the extension. `scripting` reads media information from that page. AfterWatch uses `storage` for `language` and `platformSettings`, a version 2 object containing four supported destinations and their order. Both fields are saved together through `chrome.storage.local`, without synchronization. Legacy `enabledPlatforms` discussion choices are read for migration and may remain in local storage; valid new settings take priority. Migration enables Letterboxd once while preserving discussion choices. Valid three-platform version 1 settings retain their choices/order and append IMDb, disabled. New installations enable IMDb. Later explicit choices to disable any or all platforms are retained. Initial/migrated choices and user changes are saved locally; a save failure is shown in Settings. Uninstalling clears these settings. Persistent host access is not requested.

The development preview is separate from production. `dev/preview.js` loads a local fixture through the local server and keeps separate language and platform preferences in the preview origin's localStorage; production `popup.html` never loads it.

Future live chat or external metadata lookup would change the data flow. They are not implemented in this release and would require updated privacy documentation before release.
